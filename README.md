# 跨世界陪伴角色 · CMCC

[![SillyTavern Extension](https://img.shields.io/badge/SillyTavern-Extension-blue)](https://github.com/SillyTavern/SillyTavern)

> 一个固定的角色，陪你玩**任何**角色卡。
> 她参与剧情，跟着你穿越每个世界，**记得你们经历的一切**。

**CMCC** = **C**ross-world **M**emory **C**ompanion **C**haracter
（备选缩写 **STCMCC** = SillyTavern CMCC）

---

## 这解决什么问题

SillyTavern 有成千上万张角色卡，但每张卡都是**独立的**：

- 换个卡，就换了一个世界、换了一批人
- 上一个卡里发生的事，新的卡完全不知道
- 你想要的是「**一直陪着你的那个人**」，而不是每次都从头开始

装上 CMCC 之后：

```
你在 A 世界带着她玩 → 她记住发生的一切
切到 B 世界         → 她记得 A 世界，会按自己的人设自然提起
回到 A 世界换存档    → 她记得上一次，且知道这是「另外一次」
```

**只要开启她，就算带着她一起参与。**

---

## 两个核心设计

### ① 她记得一切

所有世界、所有存档的经历，**全部是她自己的记忆**。
不是"听说过"，是"我们一起经历的"。她会按自己的性格，在最恰当的时机提起来。

### ② 但她分得清「世界」和「存档」

| 概念 | 是什么 | 例子 |
|---|---|---|
| **世界** | 不同的角色卡 / 群聊 | A 世界、B 世界 |
| **存档** | **同一个世界**里的不同聊天 | A 世界的存档1、存档2 |

**同一个世界的不同存档是两次不同的经历**，她不会混为一谈。
提起来时会说清是哪一次，不会把两件事说成一件。

---

## 记忆存在世界书里（重要）

CMCC 不把记忆藏在扩展内部，而是**写进一张真正的世界书**：

```
世界书：CMCC-记忆库
├── [CMCC] 她是谁             ← 从角色卡提取的人设（只读参考）
├── [CMCC] 共同记忆            ← 跨世界通用（你俩一直没变的事）
├── [CMCC] 世界 · char:xxx.png ← 一个世界一条
└── [CMCC] 世界 · char:yyy.png
```

每个世界词条的内容是**人类可读的 Markdown**：

```markdown
# 全球冰封 v3.1.3

## 存档1
- 在避难所里冻了一夜
- 找到一箱罐头

## 存档2
- 这次直接进了地堡
```

**这意味着三件事**：

| 好处 | 说明 |
|---|---|
| **写正文的 AI 直接读得到** | 世界书是 ST 的原生注入通道，词条是 `constant: true` 常驻注入 |
| **你可以直接改** | 用 ST 自带的世界书编辑器，或面板里点着改；改完点「重新载入」 |
| **可以备份/分享** | 就是一个普通的世界书文件，导出即可 |

## 安装

### 方式一：Git 克隆（推荐）

```bash
cd <SillyTavern>/data/default-user/extensions
git clone https://github.com/<你的用户名>/SillyTavern-CMCC.git
```

### 方式二：手动

把文件夹放进 `<SillyTavern>/data/default-user/extensions/`：

```
extensions/
└── SillyTavern-CMCC/
    ├── manifest.json
    ├── index.js
    ├── style.css
    ├── LICENSE
    └── src/
        ├── state.js      设置 + 记忆模型（纯逻辑）
        ├── store.js      记忆 ↔ 世界书 读写与序列化
        ├── inject.js     动态引导注入
        ├── topbar.js     酒馆顶部入口（改人设 / 记忆）
        └── ui.js         扩展到设置页（切换陪伴者）
```

装好后刷新 SillyTavern 页面。

## 使用

### 两个入口，分工不同

```
酒馆顶部图标栏              扩展设置页
（人形箭头图标）            （和酒馆助手同一位置）
      │                            │
      ▼                            ▼
  改「人设」+「记忆」          切换「哪个角色做陪伴者」
  日常编辑都走这里             开关 / 参数 / 记忆总览
```

**为什么这么分**：换人是低频操作，放设置页合适；改人设和记忆是高频操作，
放顶部一点就能开，不打断游玩。

### 首次使用

1. 打开 **扩展设置**，找到「**跨世界陪伴角色**」
2. **启用**开关打开
3. **陪伴角色卡**里选一张你想让她常驻的卡
4. 去玩**任何别的卡** —— 她就在场了
5. 之后改人设/记忆，点**酒馆顶部**的人形箭头图标

### 顶部面板

```
┌─ 跨世界陪伴角色 ──────────────────── [×] ┐
│ 当前陪伴者  阿米娅            [切换 →]    │
│                                          │
│ ── 人设 ──────────────────            ⟳ │
│   角色描述   罗德岛的领袖，卡特斯族…      │
│   性格       沉稳、温柔、有责任感…       │
│   场景       （空）                       │
│   开场白     （空）                       │
│                                          │
│ ── 记忆 ──────  3 个世界 / 142 条     ⟳ │
│ 当前位置：全球冰封 v3.1.3                │
│ ▶ 全球冰封 v3.1.3        2 次 / 88 条    │
│     存档1  45 条                         │
│       在避难所里冻了一夜           [×]   │
│       找到一箱罐头                 [×]   │
│       [+ 加一条]                         │
│     存档2  43 条                         │
│   漫综：世界观            1 次 / 54 条   │
│                                          │
│ [整理记忆] [打开世界书]                   │
└──────────────────────────────────────────┘
```

> 人设字段点一下就能改，**直接写回角色卡**（若未自动落盘，去角色管理点保存）。
> 「切换 →」会跳到扩展设置页并高亮本插件。

### 记忆编辑

| 操作 | 怎么做 |
|---|---|
| 改**世界名** | 点世界标题 |
| 改**存档名** | 点存档标题（比如改成"第一次玩""和XX那次"） |
| 改**单条记忆** | 点记忆文字 |
| 删单条记忆 | 记忆右侧 `×` |
| 加记忆 | 「+ 加一条」 |
| 删整个存档 | 存档标题右侧 `×` |
| **批量改** | 「打开记忆世界书」→ ST 编辑器里随便改 |

> 在 ST 编辑器里改完，回来点「**重新载入**」即可（会自动解析你手改的 Markdown）。

### 设置项

| 选项 | 说明 |
|---|---|
| 存档切换提示 | 换世界/换存档时，让她自然表现出"这是另一次经历" |
| 调试输出 | 把注入内容打到控制台（F12） |
| 自动整理(条) | 每收这么多消息整理一次记忆；0=关闭自动 |
| 冷却(秒) | 两次自动整理的最小间隔 |
| 引导预算 | 动态引导文本的 token 上限（记忆本体由世界书管，不受这个限制） |

## 工作原理

### 注入分两路

```
① 记忆本体  →  世界书 CMCC-记忆库（constant 词条，ST 原生注入）
                 写正文的 AI 直接读到，你也能编辑

② 动态引导  →  CHAT_COMPLETION_SETTINGS_READY 事件
                 身份（从角色卡取）+ 你在哪（世界/存档/来过几次）+ 怎么用记忆
```

**为什么保留动态引导**：世界书只能"塞内容"，无法告诉 AI
「你现在在存档2，存档1 是另外一次经历，别混」——这需要运行时信息。

### 注入点（已核对 ST 源码）

```js
// openai.js:3052 —— ST 把请求体对象（引用）交出来
await eventSource.emit(event_types.CHAT_COMPLETION_SETTINGS_READY, generate_data);

// 我们在这里改 generate_data.messages
generate_data.messages.splice(idx, 0, { role: 'system', content: 引导文本 });

// openai.js:3056 —— 两行之后才序列化，改动能生效
body: JSON.stringify(generate_data)
```

插在**最后一条 user 消息之前**（离当前发言最近，权重高，不打断对话结构）。
幂等保护：已有 `<cmcc_guide>` 标记就不重复注入。

### 记忆怎么攒

- 每收到 **N 条**消息（默认 12）自动触发一次整理，带冷却
- 用 `generateQuietPrompt` **静默生成**（不污染你的聊天）
- 让模型从**陪伴者视角**提取她新获得的信息，输出：
  ```json
  { "entries": ["她亲身经历或得知的事，每条一句话，不超过 40 字"] }
  ```
- 写入对应世界与存档的世界书词条

## 已知限制

| 限制 | 说明 |
|---|---|
| **只支持 Chat Completion 后端** | 依赖 `CHAT_COMPLETION_SETTINGS_READY` 做动态引导。文本补全后端只能读到世界书部分的记忆 |
| **需要手动关联世界书** | 首次使用请在 ST 的世界书设置里把 `CMCC-记忆库` 设为**全局**或挂到当前聊天，否则她读不到记忆 |
| **记忆质量依赖模型** | 摘要由你在 ST 里配的模型生成，小模型可能提取质量差 |
| **不是"角色卡带插件"** | 这是扩展，装一次对**所有**卡生效 |
| **陪伴者本人聊天不注入** | 正在和她那张卡聊天时自动跳过，避免设定重复 |

## 给创意工坊的扩展点

这些我故意**没做**，留给社区：

- **主动消息**：久未上线时她主动发一条。有了 CMCC 的记忆库，主动开口能带上"上次我们……"，效果会比单纯定时问候好得多。参考 [Time-Awareness](https://github.com/Gu-gu-gu-gu-gu/Time-Awareness) 的做法。
- **向量检索**：记忆多了以后按相关性取，而不是全量注入。
- **情绪/关系状态**：给陪伴者加好感度、心情等变量，跟着世界书一起走。
- **多陪伴者**：同时带多个人。
- **世界快照**：给每个世界生成一段"我们那时在做什么"的梗概。

## 与已有扩展的区别

| 扩展 | 做什么 | CMCC 的差别 |
|---|---|---|
| [EchoText](https://github.com/mattjaybe/SillyTavern-EchoText) | 独立界面给角色发消息 | 那个是"单独聊天"，**不参与剧情** |
| [Character-Continuity-Manager](https://github.com/jeremyoha450/SillyTavern-Character-Continuity-Manager) | 跨聊天保持角色连续性 | 那个管记忆，**不解决"出现在别的卡里"** |
| [Time-Awareness](https://github.com/Gu-gu-gu-gu-gu/Time-Awareness) | 注入时间、久未发言时主动发消息 | 那个**依附当前角色**，不能固定成"一个人" |

**CMCC = 固定一个 char + 世界书记忆 + 世界/存档区分 + 进入任意卡的剧情。**

## 开发

```bash
cd tests
node test_core.mjs      # 82 项核心逻辑测试
```

### 模块职责

| 文件 | 职责 |
|---|---|
| `index.js` | 位置同步、存档切换检测、事件接线、记忆整理、对外 API |
| `src/state.js` | 设置、标识、记忆模型（增删改）、旧版迁移 |
| `src/store.js` | 世界书读写、条目模板、Markdown 序列化 ↔ 反序列化 |
| `src/inject.js` | 动态引导组装（含 token 预算）、请求体注入 |
| `src/ui.js` | 设置面板（含记忆编辑） |

### 数据流

```
世界书 CMCC-记忆库
      │  loadWorldInfo
      ▼
   CACHE（内存模型：worlds → saves → entries）
      │                        ▲
      │  面板编辑 / 自动整理      │  saveToBook
      ▼                        │
   用户可见的可读 Markdown ──────┘
```
