> 一个固定的角色，陪你玩**任何**角色卡。
> 她参与剧情，跟着你穿越每个世界，**记得你们经历的一切**。

**CMCC** = **C**ross-world **M**emory **C**ompanion **C**haracter
（备选缩写 **STCMCC** = SillyTavern CMCC）

---

## 这解决什么问题

SillyTavern 有成千上万张角色卡，但每张卡都是**独立的**：

- 换个卡，就换了一个世界、换了一批人
- 上一个卡里发生的事，新的卡完全不知道
- 你想要的是「**一直陪着你的那个人**」，而不是每次都从头开始

装上 CMCC 之后：

```
你在 A 世界带着她玩 → 她记住发生的一切
切到 B 世界         → 她记得 A 世界，会按自己的人设自然提起
回到 A 世界换存档    → 她记得上一次，且知道这是「另外一次」
```

**只要开启她，就算带着她一起参与。**

---

## 三个核心设计

### ① 她只记得**你们共同经历**的事

不是"这一章发生了什么"，而是"**我和你一起做了什么**"。

AI 每次正文结束后另外输出一个记忆块，里面只写**她在场、和你一起经历的事**；
她不在场的剧情（别人之间的事、她只是听说的）不会被记进来。
所以她的回忆是**亲历**，不是转述。

### ② 但她分得清「世界」和「存档」

| 概念 | 是什么 | 例子 |
|---|---|---|
| **世界** | 不同的角色卡 / 群聊 | A 世界、B 世界 |
| **存档** | **同一个世界**里的不同聊天 | A 世界的存档1、存档2 |

**同一个世界的不同存档是两次不同的经历。**

### ③ 而且绝不会"出戏"

这是**硬性约束**（写死在注入提示词的最前面）：

- ❌ 不提"其他世界"、不说"上次那个世界""换世界了"
- ❌ 不说破"这是设定 / 游戏 / 剧本"，不用"存档""世界书""插件""AI"这类词
- ❌ **尤其不能对别的 NPC 说这些** —— 有别的角色在场时，她就是个普通的人

她可以自然地回忆（"我们好像也这样走过一次"），但**不会破坏当前世界观**。

> 你和她之间的"跨世界"这层关系，她自己心里清楚，但只在合适的时候用这个世界里说得通的话表达。

### ④ 记忆的取用分两路

| 来源 | 是什么 | 默认条数 |
|---|---|---|
| **最近** | 当前存档里最新发生的事 | 10 |
| **相似旧事** | 以前在**同一个世界**的类似场景 | 5 |

**相似旧事**是这样工作的：正在写"坐在车里"的剧情，插件会把记忆里也提到"车里"的旧事找出来一起注入 ——
她就会自然地想起"那次也这样坐在车里"。检索**只在本世界内进行**（跨世界会出戏）。

## 记忆存在世界书里（重要）

CMCC 不把记忆藏在扩展内部，而是**写进一张真正的世界书**：

```
世界书：CMCC-记忆库
├── [CMCC] 她是谁             ← 从人设提取，只读参考
├── [CMCC] 共同记忆            ← 跨世界通用（你俩一直没变的事）
├── [CMCC] 世界 · char:xxx.png ← 一个世界一条
└── [CMCC] 世界 · char:yyy.png
```

每个世界词条的内容是**人类可读的 Markdown**：

```markdown
# 全球冰封 v3.1.3

## 存档1
- 在避难所里冻了一夜
- 找到一箱罐头

## 存档2
- 这次直接进了地堡
```

> ⚠ 记忆**不需要挂载这张世界书**。插件是把记忆**直接注入提示词**的，
> 世界书只是给你一个用 ST 原生编辑器查看/编辑/备份的入口。

**这意味着三件事**：

| 好处 | 说明 |
|---|---|
| **写正文的 AI 直接读得到** | 记忆由插件注入请求体，不依赖世界书挂载 |
| **你可以直接改** | 用 ST 自带的世界书编辑器，或在面板里点着改 |
| **可以导出/分享** | 面板里有「导出人设+记忆」，一个 JSON 带走全部 |

## 使用

### 两个入口，分工不同

```
酒馆顶部图标栏              扩展设置页
（人形箭头图标）            （和酒馆助手同一位置）
      │                            │
      ▼                            ▼
  改「人设」+「记忆」          切换「哪个角色做陪伴者」
  日常编辑都走这里             开关 / 参数 / 记忆总览
```

**为什么这么分**：换人是低频操作，放设置页合适；改人设和记忆是高频操作，
放顶部一点就能开，不打断游玩。

### 首次使用（默认：独立内置角色）

1. 打开 **扩展设置**，找到「**跨世界陪伴角色**」
2. **陪伴角色** 里选 `● 内置角色（独立）`（默认就是这个）
3. 填 **名字 / 角色描述 / 性格 / 与你的关系**
4. 勾上 **启用**
5. 去玩**任何一张卡** —— 她就在场了

> **不需要挂载世界书**。她的记忆由插件直接注入提示词，
> 人设也存在插件自己这里，**不写进角色卡库、不占用原生世界书**。

想用角色库里已有的卡？把 **陪伴角色** 切成 `○ 用已有角色卡` 再选一张即可。

### 记忆默认是空的

这是**正常的** —— 默认只有人设，没有任何记忆条目。

开始玩之后，她会一边玩一边把值得记的事记下来（见下方「记忆是她自己记的」）。
她去过的地方会**按需自动出现**，不会预先堆一堆空存档。

| 操作 | 怎么做 |
|---|---|
| 改**世界名** | 点世界标题 |
| 改**存档名** | 点存档标题（比如改成"第一次玩""和XX那次"） |
| 改**单条记忆** | 点记忆文字 |
| 删单条记忆 | 记忆右侧 `×` |

### 设置项

| 选项 | 说明 | 默认 |
|---|---|---|
| **人设预设** | **多个内置人设并存**，下拉切换；新建 / 复制 / 改名 / 删除 | 1 个 |
| **导出人设+记忆** | 一个 JSON 带走人设和全部记忆 | — |
| **导入** | 记忆按内容去重合并，不覆盖 | — |
| 存档切换提示 | 换世界/换存档时，让她自然表现出"这是另一次经历" | 开 |
| 读取正文记忆块 | 读 AI 输出的 ` ```cmcc ` 块，自动记进记忆 | 开 |
| 注入记忆 | 把记忆直接注入提示词（关掉就只靠世界书，需手动挂载） | 开 |
| 同步世界书 | 额外写一份 `CMCC-记忆库`，便于用 ST 编辑器查看/编辑 | 开 |
| 调试输出 | 把注入内容打到控制台（F12） | 关 |
| 自动整理(条) | 每收这么多消息整理一次；0=关闭自动 | 12 |
| 冷却(秒) | 两次自动整理的最小间隔 | 90 |
| **引导预算** | 人设+底线+格式说明的 token 上限 | **2400** |
| **最近记忆(条)** | 注入多少条「最近」（建议 5~10） | **10** |
| **相似旧事(条)** | 注入多少条「相似旧事」（建议 2~5） | **5** |
| **记忆预算** | 记忆注入的 token 上限 | 1800 |

> **预算的实测数字**（我量过）：一个正常完整的人设（约 1400 字）+ 底线 + 格式说明，
> 固定占 **约 1070 token**；20 条记忆（每条 50 字左右）约 **630 token**。
> 所以**引导预算给 2400** 才够 —— 早先默认 600 会把你的角色描述砍掉一半。

### 多个内置人设（预设）

内置角色不写进角色卡库，人设存在扩展设置里。**可以存多个**：

```
[小满 ▾]  [新建] [复制] [改名] [删除]
```

| 操作 | 说明 |
|---|---|
| 下拉切换 | 同时换掉她的**名字 / 描述 / 性格 / 与你的关系** |
| 新建 | 建一个空人设 |
| 复制 | 复制当前人设全部内容（改名即可做变体） |
| 改名 | 只改**预设名**（上面的"名字"字段是角色名） |
| 删除 | 至少保留一个；**记忆不会跟着删** |

> 老版本只有一个 `builtin` 对象，升级时**自动迁移**成列表第一项，不会丢。

### 导出 / 导入

点「**导出人设+记忆**」得到一个 JSON：

```json
{
  "_cmcc": true,
  "_version": 1,
  "persona": { "name": "小满", "description": "…", "personality": "…", "scenario": "…" },
  "worlds": { "char:xxx.png": { "label": "全球冰封 v3.1.3", "saves": { } } }
}
```

导入时**记忆按内容去重**追加（不覆盖你现有的），人设可选**作为新预设加入**或**覆盖当前**。

## 记忆是她自己记的（MVU 式）

和 MVU 变量的思路一样：**AI 每次生成正文后，在末尾输出一个代码块，插件直接读它。**

````
```cmcc
和她一起在雪地里走了很久，她一直走在迎风那一侧
她把手套让给 {user}，自己揣着手说不冷
```
````

**一行一条，直接写内容** —— 不用写范围、不用编号、不用加 `+` 前缀。
你在哪个存档、哪个世界，插件自己检测。

**唯一的硬性要求：只写你和 {user} 两个人共同经历的事。**

| 该记 ✅ | 不该记 ❌ |
|---|---|
| 你和 {user} 一起做了什么 | 别人之间发生的事 |
| 你们一起到过的地方 | 她不在场时的剧情 |
| 一起遇到的人、共同的约定 | 她只是"听说"的情报 |
| 每条 30~50 字，写具体 | "一起去了某地"这种一句话概括 |

> 这样她的回忆才是**亲历**而不是转述 —— 你没带她去的场合，她不该记得。

**调用链**：

```
AI 输出正文 + ```cmcc 块
        ↓  MESSAGE_RECEIVED
   parseMemoryCommands()      解析（纯文本行 / JSON / 旧格式都认）
        ↓
     writeMemory()            写进当前世界 + 当前存档
        ↓                      没有有效聊天 ID 时**不建存档**（防存档爆炸）
      注入时再读回来
```

**世界名就是当前角色卡的名字，存档名就是当前聊天** —— 你不用手动起名。

> 插件**只认共同记忆块**。预设自带的 `<summary>` 摘要不会被当记忆存 ——
> 摘要记录的是整节剧情（含她不在场的部分），和她"亲历"的记忆不是一回事。

### 这个块会显示在正文里吗

会，但**有专属样式**：蓝色左边框 + 顶部标一个「她的记忆」，一眼看出不是普通代码块。

想完全隐藏，用酒馆自带的**正则**扩展加一条：

```
查找：  /```cmcc[\s\S]*?```/gs
替换：  （留空）
```

> 插件本身也能去掉（`stripBlocks`），但**默认不碰你的正文** ——
> 显示层交给你，插件只读不写，不会和别的正则打架。

### 解析很宽松

- 纯文本行（推荐）、JSON（`{"memory":[…]}`）、旧格式（`+范围|类型|内容`）都认
- 语言标记大小写不敏感，也认 `memo` / `memory`
- **不误吃普通代码块**（` ```js ` 之类不会被当成记忆）
- **含 ST 宏 `{user}` 的行不会被误判成 JSON**（曾经会 → 整块记忆全丢，已修）
- 坏 JSON **不抛错**，只是不记，正文照常显示
- 单条最长 500 字，一次最多 20 条

## 工作原理

### 注入分两路

```
① 动态引导  →  CHAT_COMPLETION_SETTINGS_READY 事件
                 ① 人设（你是谁，最高优先级）
                 ② 位置（当前世界）
                 ③ 底线与规则（绝不能出戏）
                 ④ 记忆块格式说明

② 记忆本体  →  同一个事件，拼在引导之后
                 最近 N 条（当前存档）+ 相似旧事（同世界检索）+ 共同记忆
```

**两者都直接进请求体**，不依赖世界书挂载 —— 所以插件会告诉你「记忆已直接注入，不需要挂载世界书」。

`同步世界书` 开着时，额外写一份 `CMCC-记忆库` 供你查看 / 编辑 / 备份，但那不是注入通道。

**顺序有讲究**：人设永远排在记忆**之前**（用户要求「优先读取插件的人设，再读记忆」）。
预算不够时压缩的也是人设（且有 260 字下限），**底线与规则永不压缩**。

### 注入点（已核对 ST 源码）

```js
// openai.js:3052 —— ST 把请求体对象（引用）交出来
await eventSource.emit(event_types.CHAT_COMPLETION_SETTINGS_READY, generate_data);

// 我们在这里改 generate_data.messages
generate_data.messages.splice(idx, 0, { role: 'system', content: 引导文本 });

// openai.js:3056 —— 两行之后才序列化，改动能生效
body: JSON.stringify(generate_data)
```

插在**最后一条 user 消息之前**（离当前发言最近，权重高，不打断对话结构）。
幂等保护：已有 `<cmcc_guide>` 标记就不重复注入。

### 记忆怎么攒

- 每收到 **N 条**消息（默认 12）自动触发一次整理，带冷却
- 用 `generateQuietPrompt` **静默生成**（不污染你的聊天）
- 让模型从**陪伴者视角**提取她新获得的信息，输出：
  ```json
  { "entries": ["她亲身经历或得知的事，每条一句话，不超过 40 字"] }
  ```
- 写入对应世界与存档的世界书词条

## 已知限制

| 限制 | 说明 |
|---|---|
| **只支持 Chat Completion 后端** | 依赖 `CHAT_COMPLETION_SETTINGS_READY` 做动态引导。文本补全后端只能读到世界书部分的记忆 |
| **记忆质量依赖模型** | 记忆块由你配的模型生成，小模型可能提取质量差 |
| **不是"角色卡带插件"** | 这是扩展，装一次对**所有**卡生效 |
| **陪伴者本人聊天不注入** | 正在和她那张卡聊天时自动跳过，避免设定重复 |
| **相似旧事是关键词匹配，不是向量检索** | 用 2~3 字汉字片段的重合度排序，对"车里""火堆"这类具体名词有效，对抽象语义相似无能为力。向量检索在路线图上 |
| **她是否出戏，最终取决于模型** | 提示词里写了硬性约束，但小模型可能不完全遵守 |

## 给创意工坊的扩展点

这些我故意**没做**，留给社区：

- **主动消息**：久未上线时她主动发一条。有了 CMCC 的记忆库，主动开口能带上"上次我们……"，效果会比单纯定时问候好得多。参考 [Time-Awareness](https://github.com/Gu-gu-gu-gu-gu/Time-Awareness) 的做法。
- **向量检索**：记忆多了以后按相关性取，而不是全量注入。
- **情绪/关系状态**：给陪伴者加好感度、心情等变量，跟着世界书一起走。
- **多陪伴者**：同时带多个人。
- **世界快照**：给每个世界生成一段"我们那时在做什么"的梗概。

## 与已有扩展的区别

| 扩展 | 做什么 | CMCC 的差别 |
|---|---|---|
| [EchoText](https://github.com/mattjaybe/SillyTavern-EchoText) | 独立界面给角色发消息 | 那个是"单独聊天"，**不参与剧情** |
| [Character-Continuity-Manager](https://github.com/jeremyoha450/SillyTavern-Character-Continuity-Manager) | 跨聊天保持角色连续性 | 那个管记忆，**不解决"出现在别的卡里"** |
| [Time-Awareness](https://github.com/Gu-gu-gu-gu-gu/Time-Awareness) | 注入时间、久未发言时主动发消息 | 那个**依附当前角色**，不能固定成"一个人" |

**CMCC = 固定一个 char + 世界书记忆 + 世界/存档区分 + 进入任意卡的剧情。**

## 仓库结构

**`main` 分支只放插件本体** —— 克隆/下载下来就能直接装，没有多余东西。

```
SillyTavern-CMCC/
├── manifest.json          ST 读这个识别扩展
├── index.js               入口
├── style.css
├── src/                   插件自己的模块
│   ├── state.js           设置 + 内置人设列表 + 记忆模型
│   ├── store.js           世界书读写、Markdown 序列化
│   ├── inject.js          动态引导组装、相关记忆检索、注入
│   ├── memo.js            解析 AI 输出的记忆块
│   ├── portable.js        导出/导入的纯逻辑
│   ├── summary.js         读预设自带摘要的能力（当前不接入）
│   ├── topbar.js          酒馆顶部入口
│   └── ui.js              设置面板
├── presets/               可直接导入的角色预设
└── docs/                  安装说明
```

运行时**只需要上面这些**（9 个代码文件，约 200 KB）。

### 开发相关的东西在 `dev` 分支

测试、开发工具、排查笔记都在 [`dev` 分支](https://github.com/WhiteShawqi/SillyTavern-CMCC/tree/dev)：

| 目录 | 是什么 |
|---|---|
| `tests/` | Node 测试（假 DOM）+ 浏览器验证页 |
| `tools/` | 无头浏览器命令行（`shot.mjs`）、GitHub 连接排查脚本 |
| `docs/` | 发布流程、诊断脚本等排查记录 |

```bash
git clone -b dev https://github.com/WhiteShawqi/SillyTavern-CMCC.git
cd SillyTavern-CMCC

# Node 测试（假 DOM，不执行 CSS）
cd tests && node test_core.mjs

# 真浏览器验证（真实布局 + 真实 CSS）—— 涉及样式改动必跑
node tests/layout/run.mjs
```

> 为什么分开：这些是**开发时才需要的**。普通用户 clone 下来只要装进酒馆，
> 不需要 40 多个测试文件。需要的人切 `dev` 分支就有。

### 模块职责

| 文件 | 职责 |
|---|---|
| `index.js` | 位置同步、存档切换检测、事件接线、记忆整理、对外 API |
| `src/state.js` | 设置、内置人设列表、记忆模型（增删改）、旧版迁移 |
| `src/store.js` | 世界书读写、条目模板、Markdown 序列化 ↔ 反序列化 |
| `src/inject.js` | 动态引导组装（含 token 预算）、相关记忆检索、请求体注入 |
| `src/memo.js` | 解析 AI 输出的记忆块（纯文本 / JSON / 旧格式） |
| `src/portable.js` | 导出/导入的纯逻辑（可单测） |
| `src/summary.js` | 读预设自带 `<summary>` 摘要的能力（当前不接入记忆流程） |
| `src/selection.js` | 记忆树的折叠状态、多选集合、三级级联勾选（纯状态，不碰 DOM） |
| `src/editor.js` | 弹出式编辑器：标签页 + 内部折叠（人设 / 记忆 / 更新 / 备份 / 赞助） |
| `src/ui.js` | 设置面板（人设预设 / 导出导入 / 参数 / 记忆总览） |
| `src/topbar.js` | 只剩工具函数（打开世界书面板、判断世界书有没有挂载） |

### 数据流

```
世界书 CMCC-记忆库
      │  loadWorldInfo
      ▼
   CACHE（内存模型：worlds → saves → entries）
      │                        ▲
      │  面板编辑 / 自动整理      │  saveToBook
      ▼                        │
   用户可见的可读 Markdown ──────┘
```
